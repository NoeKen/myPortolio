# Offre « Services » — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Ajouter une section aperçu « Services pour PME » sur l'accueil, une page `/services` complète avec un formulaire de demande de maquette, un lien dans la Navbar, et brancher l'envoi réel des messages par Resend.

**Architecture :** Tout le contenu vit dans `src/datas/services.ts`. Une carte `PlanCard` (variantes `compact` et `full`) sert à l'accueil et à `/services`. La page `/services` assemble six sections de `src/components/services/` et réutilise `ContactForm` + `useContactForm`, avec un sujet prérempli. `/api/contact` envoie le courriel par Resend, côté serveur.

**Tech Stack :** Next.js 16 (Pages Router), React 18, TypeScript strict, Tailwind, shadcn/ui (`Card`, `Badge`, `Button`, `Accordion`), Framer Motion (`SectionAnimation`), react-hook-form + zod, `resend`.

**Spec :** `docs/superpowers/specs/2026-10-25-services-design.md`. Le texte exact (forfaits, déroulement, inclus, modalités, FAQ, titres) est dans la spec : copiez-le **mot pour mot** depuis la spec, ne le réécrivez pas.

## Global Constraints

- Tout le texte visible est en français.
- **Aucun prix** sur l'accueil (ni « $ », ni montant). Prix « à partir de » + « taxes en sus » sur `/services` seulement.
- Prix formatés en `fr-CA` : `price.toLocaleString("fr-CA") + " $"` → « 1 500 $ ».
- Couleurs uniquement via les tokens existants (`primary`, `muted-foreground`, `accent`, `border`…). Aucune couleur codée en dur. Mode sombre inchangé.
- Secrets (`RESEND_API_KEY`) jamais dans `.env` (suivi par git) : seulement dans `.env.local` et dans Vercel.
- Dépendance : `resend@6.32.1`, version fixée (publiée il y a plus de 2 semaines).
- Le corps du courriel est en texte brut (`text`), jamais construit en HTML à partir de la saisie.
- Base de lint : il y a **déjà 1 erreur** avant ce chantier (`src/components/layout/Navbar.tsx:18`, `react-hooks/set-state-in-effect`). Aucune tâche ne doit en ajouter. `npm run build` passe aujourd'hui et doit continuer à passer.
- Le projet n'a pas de suite de tests et on n'en ajoute pas (spec §5). Chaque tâche se vérifie avec `npx tsc --noEmit`, `curl` contre `npm run dev`, ou des assertions JS dans le navigateur, données mot pour mot ci-dessous.
- Rien n'est poussé. Un commit par tâche, sur `feat/services`, avec ce pied de message :
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **Resend renvoie `{ error }` au lieu de lever une exception.** Le SDK ne lève pas d'exception sur une clé invalide : il renvoie `{ data: null, error }`. Une clé invalide doit donner un 500 avec le message de repli, pas un 200. → Task 1, step 4, vérification 3.
2. **Lien direct `/services#maquette`, ouvert depuis un courriel.** La section doit apparaître sous la Navbar collante, pas cachée dessous. → `scroll-mt-20` sur chaque section qui a un `id`, Task 4, step 7, vérification 2.
3. **Après un envoi réussi, `form.reset()`.** Le sujet doit revenir à « Maquette gratuite » sur `/services`, et non à vide. Sur l'accueil, il reste vide comme avant. → Task 4, step 1 et step 7, vérification 4.
4. **Saisie contenant du HTML** (`<script>` dans le nom ou le message) : acceptée (200), transmise telle quelle en texte brut. → Task 1, step 4, vérification 4.
5. **Largeur cellulaire (375 px)** avec 4 cartes sur l'accueil et 3 cartes + la bande Entretien sur `/services` : aucun défilement horizontal. → Task 3, step 4, et Task 4, step 7, vérification 1.
